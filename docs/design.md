# 设计与验收边界

状态：首版生产代码和自动化测试已实现；macOS、Windows、Linux 实机 SSH/PostgreSQL 验收及 100 并发验收尚未完成。

## 已确认需求

- npm CLI 分发，TypeScript 开发，pnpm 管理依赖，ESLint 与 Prettier 检查。
- 首版覆盖 macOS、Windows、Linux，本机运行。
- 客户端连接固定的本地端点；首版固定监听 `127.0.0.1` 并显式配置 TCP 端口，不允许公开监听或随机端口。
- 支持多个 SSH 主机，每个目标绑定一台 SSH 主机；同一 SSH 主机可承载多个目标。
- 数据库目标允许主机名或 IP 地址，由 SSH 主机所在网络解析和访问。
- PostgreSQL 认证与 TLS 数据原样传输，不解析 SQL、不持有数据库凭据。
- 每个 SSH 主机明确选择 agent、私钥文件或交互输入密码之一；密码和私钥口令不得出现在配置中。首次连接确认服务器指纹，后续身份变化拒绝连接。
- SSH 断线时关闭受影响的数据库连接并自动重连 SSH；恢复后接受新连接，不重放 SQL 或恢复事务。
- 启动前严格校验配置；未知字段、重复本地端口、无效 SSH 主机引用、无效端口、不可读私钥、非环回监听以及落盘秘密均拒绝启动。
- 用户主目录下统一使用 `.pg-ssh-proxy/`，存放配置及日志；目录管理遵循根目录 `AGENTS.md`。

## 用户目录

```text
~/.pg-ssh-proxy/
├── AGENTS.md      # 本次建立的目录管理约定
├── config.json    # 实现配置格式后创建；不含密码或私钥口令
├── logs/          # 连接生命周期、错误阶段和汇总指标
├── known_hosts   # 首次确认后保存的 SSH 主机身份
└── runtime.json  # 当前前台实例的非敏感摘要，正常退出时删除
```

## 配置校验与写入

- `config validate` 完整扫描后一次列出全部错误，并为每项显示配置路径、具体原因和下一步操作。
- `authentication` 只允许 `agent`、`identityFile` 和 `password` 三种严格互斥结构。
- 私钥路径只接受绝对路径或 `~/`，不展开环境变量；目标必须是当前用户可读的普通文件。
- 配置中出现 `password`、`passphrase`、`privateKey` 等秘密字段时给出专项安全错误。
- 代理名称、SSH 主机名称和本地端口必须唯一；相同数据库目标可以由不同本地端口或 SSH 主机访问。
- CLI 修改配置时先写入同目录临时文件，完成落盘后原子替换 `config.json`；失败时保留原配置，不维护额外长期备份。
- 用户目录仅允许当前用户访问，`config.json` 仅允许当前用户读写；具体权限语义必须分别在 macOS、Linux 和 Windows 实机验证。

这里的 `~` 表示启动 CLI 的当前普通用户主目录。配置、主机身份记录和日志应限制为该用户可访问；跨平台权限控制待验证。

## 已确认的配置模型

- `sshHosts` 以稳定 ID 定义可复用的 SSH 连接及唯一认证方式。
- `proxies` 以稳定 ID 定义本地端口、SSH 主机引用和数据库目标；固定的 `127.0.0.1` 不写入配置。
- `sshHosts` 和 `proxies` 的键同时是用户可见名称与稳定引用，只允许小写字母、数字和连字符。
- 首版配置不添加无当前用途的 `version` 字段，不实现未被要求的兼容层。
- `config.json` 是唯一配置事实来源；交互式向导是普通用户的主入口，高级用户可手工维护后使用 `config validate`。
- 向导不询问已固定的 `127.0.0.1`，但显式回显最终本地端点、SSH 主机和数据库目标。
- 配置保存前必须显示完整路径摘要；错误必须同时给出失败阶段、具体原因和下一步操作。

```json
{
  "sshHosts": {
    "production": {
      "host": "bastion.example.com",
      "port": 22,
      "username": "deploy",
      "authentication": {
        "type": "agent"
      }
    }
  },
  "proxies": {
    "orders-db": {
      "localPort": 15432,
      "sshHost": "production",
      "target": {
        "host": "postgres.internal",
        "port": 5432
      }
    }
  }
}
```

上例为首版完整字段契约，未列出的字段一律拒绝。

## 已确认的 CLI 交互

- 零参数运行：无配置时进入首次向导，有效配置直接前台启动全部代理，无效配置不启动任何代理。
- 用户命令仅使用 `add`、`edit [name]`、`remove [name]`、`list` 和 `check [name]`；高级入口为 `config path` 与 `config validate`。
- 向导先完成本地校验并原子保存，再测试 SSH 与数据库可达性；外部连接失败不丢弃已验证的配置。
- 添加代理时优先选择已有 SSH 主机；新主机名称由系统建议，用户可修改。
- 本地端口从 `15432` 开始建议当前可用值，保存前显式回显并固定写入配置。
- 配置错误导致全部拒绝启动；运行时单个 SSH 主机失败只影响依赖它的代理，其他代理继续服务。
- 默认回显只包含用户行动所需信息；`--verbose` 增加错误阶段、耗时、重试次数和已过滤技术细节。

## 已确认的 fullscreen 运行界面

- 交互式 TTY 默认进入 fullscreen 均衡视图：左侧代理状态、中间实时连接事件、右侧选中连接详情。
- `REQ` 仅表示本地客户端连接请求；`RES` 仅表示 SSH 通道和数据库目标的连接结果；`CLOSE` 表示关闭原因及汇总指标。不表示 PostgreSQL 业务请求或响应。
- 每条连接最多生成 `REQ`、`RES` 和 `CLOSE` 三类界面事件，使用稳定 `connectionId` 关联；界面默认仅保留最近 500 条。
- 不显示或保存 SQL、SQL 参数、认证报文、数据库返回行或原始数据库字节。
- 非 TTY、输出重定向、CI 或不支持 fullscreen 的终端自动降级为逐行输出；`--no-ui` 可显式关闭 fullscreen。
- 首版快捷键仅包含：上下选择、`Enter` 查看连接、`/` 过滤、`Space` 暂停界面滚动、`r` 立即重试、`?` 帮助、`q` 正常退出；`Ctrl+C` 与 `q` 遵循相同清理语义。

## 已确认的运行与故障语义

- 未知 SSH 主机身份在进入 fullscreen 前显示主机、密钥类型和 SHA-256 指纹，用户确认后写入 `known_hosts`。
- SSH 主机密钥变化时正常启动直接拒绝连接并显示旧新指纹；只能通过 `check <name>` 流程核实，并输入完整 SSH 主机名后替换。
- SSH 断线后按 `1s → 2s → 5s → 10s → 30s` 重连，之后维持 30 秒一次；fullscreen 显示倒计时，`r` 可立即重试，成功后重置退避。
- SSH 断线时立即关闭受影响的已有数据库连接；本地端点继续监听，新连接立即失败而不排队；恢复后只接受新连接。
- `q` 或第一次 `Ctrl+C` 停止接受新连接，最多等待现有连接 10 秒并显示剩余数和倒计时；再次退出或到期时强制关闭。
- 代理运行时拒绝 `add`、`edit` 和 `remove`，引导用户先正常退出；只读的 `list`、`check`、`config path` 和 `config validate` 仍可执行。
- 零参数首次配置完成并通过本地校验后，立即测试连接并进入 fullscreen，不要求用户再次执行启动命令。
- 启动时每个 `sshHost` 主动建立一个 SSH 连接，其下所有代理和数据库连接分别使用 `forwardOut` channel；首版不建立 SSH 连接池。
- 交互密码或私钥口令在启动时每个 SSH 主机仅询问一次，只保留在当前进程内存中供自动重连使用，进程退出后丢弃。
- 只允许一个主运行进程；第二次启动回显现有 PID、代理数和启动时间，不再启动端口或 SSH 连接。
- 首版只以前台进程运行，不提供 daemon、系统服务、自启动或托盘程序。
- 用户状态仅使用 `starting`、`ready`、`retrying`、`unavailable` 和 `stopping`；所有界面同时使用文字和符号，不只依赖颜色。
- 不支持颜色或 Unicode 的终端自动降级为纯文本状态，例如 `[READY]` 与 `[ERROR]`。
- fullscreen 在正常退出、未捕获异常、`SIGINT` 和 `SIGTERM` 时均尝试恢复备用屏幕、光标和终端输入模式，再输出最终错误摘要。

## 日志边界

- 日志仅使用 JSONL；每次 CLI 调用使用独立的 `~/.pg-ssh-proxy/logs/pg-ssh-proxy-<runId>.log`，避免主代理与并发 `check`、`config validate` 互相争用轮转文件。
- 每次调用的单文件达到 5 MiB 后轮转，最多保留当前文件和 4 个轮转文件，该次调用上限约 25 MiB。
- 日志目录最多保留 20 次已结束调用且这些文件合计不超过 100 MiB；每次打开或关闭日志时在跨进程锁内删除最旧的非活跃调用。活跃调用持有独立租约，不会被清理；并发活跃期间目录可暂时超过上限，调用结束后收敛。
- 每条日志包含 `runId`、程序版本、PID、Node.js 版本、平台和架构，用于关联同一次运行及还原环境。
- 记录运行启动、就绪、停止和失败，`check` 的配置、凭据、SSH 与转发阶段，SSH 状态变化，以及连接级 `REQ`、`RES`、`CLOSE`。
- 失败日志必须记录阶段、错误名称和原始系统错误码；记录代理名、SSH 主机名、`connectionId`、耗时和流量汇总。
- 日志流 fatal error 必须安全停止代理并在终端提示；轮转 warning 只提示、不停止仍可用的代理。
- 不记录原始数据库字节、SQL、SQL 参数、结果集、密码、口令或私钥内容。

## 验收

- 并发规模：100 条同时连接，其中 20 条持续活跃；这是已确认的测试规模，不是已达到的性能结论。
- 记录硬件、系统、版本、网络条件、数据规模、吞吐、延迟、CPU 和内存，对比同环境 SSH 转发基线。吞吐和延迟尚无硬阈值。
- 验证多 SSH 目标隔离、认证失败、身份变化、SSH 断线重连、慢读写背压、连接资源释放。
- 每个平台使用真实 PostgreSQL 客户端连接本地端点，验证查询、TLS 和大数据传输。
- 验证本地端口冲突在建立 SSH 连接前报错，且任何本地端点都不对外网卡开放。
